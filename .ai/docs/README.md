# `.ai/docs` — the design record

The [README](../../README.md) documents what the package does and how to use it. These files
document **why it is built this way**, so a later change does not quietly undo a decision.

| File | Read it when |
|---|---|
| [design-history.md](design-history.md) | Changing the shape of the thing — phases, steps, config, what a verdict means. Says what was chosen, what it was chosen over, and what is rejected on purpose |
| [invariants.md](invariants.md) | **Before touching `src/Run/`, `src/Runner/` or `src/Mcp/`.** The five rules that cannot bend, every way a run could be green and wrong, and the defects that already broke them once |
| [laravel-mcp-notes.md](laravel-mcp-notes.md) | Working in `src/Mcp/`, or writing a test that goes through the server. Verified `laravel/mcp` v0.9.4 behaviour, including two traps that cost real time |

The original implementation spec and its explainer page are **not** here. This is a public
repository, and both documents are full of one private application's provenance — issue numbers,
branch names, domain classes and file paths. They are archived in that application's own
repository instead. See [anonymize-public-examples](../guidelines/anonymize-public-examples.md);
everything in this directory has to pass it.

## A note on discoverability

Nothing loads these automatically. `CLAUDE.md` and `AGENTS.md` in this repo are generated by
`boost-core` and any edit to them is overwritten on the next `vendor/bin/boost sync`, so the
pointer lives in the hand-maintained `README.md` instead.
